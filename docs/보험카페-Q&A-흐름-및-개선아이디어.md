# 보험카페 Q&A 전체 흐름 & 개선 아이디어 정리

## 1. 현재 Q&A 전체 흐름 (코드 기준)

### 1.1 사용자 입력

- **상품명** (예: 운전자보험, 실손보험)
- **질문 제목 / 질문 본문** (직접 입력 또는 "상품명 → AI 완성" / "정말 귀찮다"로 자동 생성)
- **설계서 이미지** (선택, 업로드 시 자동 분석 가능)
- **대상 고객·핵심 고민·답변 강조 포인트·톤·답변 길이** 등
- **대화형 모드**: 항상 켜짐 (`conversationMode = true`)
- **대화 횟수**: 고정값 **8** (`DEFAULT_CONVERSATION_LENGTH = 8`) → API에서 `conversationLength: 8` 로 전달
- **후기성 댓글 개수**: 0 / 1 / 2 중 선택 (`reviewCount`)

### 1.2 API 생성 단계 (`/api/generate-qa`)

| 단계 | 내용 | 결과물 |
|------|------|--------|
| **Step 1** | 질문 확정 | `question.title`, `question.content` (화면의 "질문글") |
| **Step 2** | 전문가 첫 답변 생성 | `answer.content` (화면의 "전문가 답변" 1개) |
| **Step 3** | 대화형 스레드 생성 | `conversation` 배열 (첫 답변 **이후** 이어지는 댓글들) |
| (선택) | 후기성 문구 | 고객 역할 후기 0~2개, 스레드 중간(마지막 설계사 댓글 직전)에 삽입 |

### 1.3 "답글"이 몇 개로 나오는지

- **첫 답변**: 1개 (전문가 답변 = "답글" 1개에 해당)
- **대화형 스레드**: API에서 `totalSteps = 8` 기준으로 **step 3 ~ 8** 까지 **6번** 반복 → **6개 메시지** (고객/설계사 번갈아가며)
- **후기성 댓글**: 0개 / 1개 / 2개 (고객만, 설계사 대답 없음)

그래서 **스레드에 보이는 댓글 수**는:

- **대화형만**: 6개  
- **대화형 + 후기 1개**: 7개 (후기 1개가 설계사 댓글 직전에 끼어듦)  
- **대화형 + 후기 2개**: 8개  

→ 사용자 느낌대로 **총 6~8개** 정도 나오는 구조가 맞음.  
(여기서 말하는 "대댓글"은 이 **대화형 스레드 안의 댓글들**을 의미하는 것으로 이해함.)

### 1.4 화면에 나오는 순서 (요약)

1. **질문글** (제목 + 본문)
2. **전문가 답변** 1개 (첫 답글)
3. **대화형 댓글 스레드** (고객 ↔ 설계사 번갈아, 6개)
4. 그 중간 어딘가에 **후기성 댓글** 0~2개 삽입

## 2. 개선 아이디어 정리 (구현 X, 정리만)

### 2.1 연관 베스트 키워드 5개

- **의도**  
  상품명(예: 운전자보험)이 정해지면, 그 글(질문/답글 영역)에 **연관 베스트 키워드 5개**를 같이 노출하고 싶다.
- **예시**  
  상품명: "운전자보험"  
  → 키워드 예: `운전자보험 추천`, `운전자보험 비교`, `운전자보험 가입조건`, `운전자보험 보장내용`, `운전자보험 보험료` (실제는 검색량/트렌드 기반으로 5개 선정)
- **고려할 점**  
  - 키워드 5개의 **출처**:  
    - (A) 상품명 + AI로 "연관 검색어/베스트 키워드 5개" 생성  
    - (B) Google 트렌드/검색 API 등으로 실검/연관어 수집 후 5개 선정  
    - (C) 사전 정의 리스트(상품별 키워드 매핑)  
  - **노출 위치**:  
    - 질문글 위/아래, 또는 전문가 답변 위/아래, 또는 "이 글의 키워드" 블록 등  
  - **형식**: 해시태그(#), 쉼표 구분, "연관 키워드: …" 문구 등 (디자인/정책에 맞게 결정)

→ **정리**: 상품명 기준으로 **연관 베스트 키워드 5개**를 정해 주고, 그걸 **Q&A 글(질문 또는 답글 영역)에 함께 노출**하는 기능을 추가하는 것이 목표.

---

### 2.2 대댓글은 총 4개만

- **현재**  
  대화형 스레드가 **6개** (+ 후기 0~2개 → 총 6~8개).
- **희망**  
  **대댓글은 총 4개**만 나오게 하고 싶다.
- **구체화**  
  - "대댓글 4개" = **대화형 스레드 메시지를 4개**로 줄인다는 의미로 이해함.  
    (첫 답변 1개 + 대댓글 4개 = 총 답글 5개처럼 보이게)
  - 구현 관점:  
    - `conversationLength` 또는 `totalSteps` 를 **6이 아니라 4**가 되도록 조정하거나,  
    - step 3~6 만 생성하도록 해서 **스레드 메시지 = 4개**로 제한.
  - **후기성 댓글**은 그대로 둘지, 4개에 포함시킬지(예: 대화 2개 + 후기 2개 = 4개)는 정책 결정 후 반영하면 됨.

→ **정리**: 지금 6~8개 나오는 **대댓글(대화형 스레드)** 을 **4개**로 줄이는 설정/로직을 넣는 것이 목표.

## 3. 요약 표

| 항목 | 현재 | 개선 아이디어 |
|------|------|----------------|
| **연관 키워드** | 없음 | 상품명 기준 **연관 베스트 키워드 5개** 선정 후, 질문/답글 영역에 함께 노출 |
| **대댓글(스레드) 개수** | 6개 (+ 후기 0~2 → 총 6~8개) | **대댓글 총 4개**로 제한 (스레드 4개 또는 스레드+후기 합 4개 등 정책에 맞게) |

위 내용은 **아이디어·요구사항 정리**만 한 것이고, 코드 변경은 하지 않은 상태입니다. 구현 시에는 키워드 5개 출처/노출 위치와 대댓글 4개 정의(스레드만 4개 vs 후기 포함 4개)를 먼저 정한 뒤 적용하면 됩니다.
