## 2. 부족한 부분 및 원인

### 2.1 본문 — 문단 구분 없음 (body_no_paragraph)
- **게이트 결과**: 본문 90점, 실패  
  - “문단 구분 없음 (200자 이상인데 빈 줄이 없음)”
- **failureTag**: `body_no_paragraph`
- **의미**: 본문이 451자로 200자 초과인데, 빈 줄(`\n\n`)이 없어 한 덩어리로 인식됨.

**원인 추정**  
- 정제 단계에서 `forceThreeBlockParagraphs()`가 적용되지만,  
  “문장”을 `.?！!.\n` 기준으로만 나누기 때문에:
  - 문장이 3개 미만으로 인식되면 문단을 넣지 않고 원문을 그대로 반환함.
  - 또는 문장 경계가 불명확해(예: 마침표/물음표 부족) 분리가 되지 않았을 수 있음.

**개선 제안**  
1. **후처리 완화**: 문장이 2개여도 길이만 200자 이상이면 빈 줄 1곳이라도 삽입 (예: 중간 문장 경계 `.` `?` 뒤에 `\n\n`).  
2. **프롬프트 보강**: Step 1 질문 생성 시 “본문은 2~3문단으로 나누어 작성하고, 문단 사이에 빈 줄을 넣어주세요” 명시.

### 2.2 키워드 건강 — 검색량 미확인 (keyword_zero_volume)
- **게이트 결과**: keywordHealth 85점, 경고  
  - “모든 키워드 검색량 0 또는 미확인, marketHeadKeyword 검색량 미확인 (unavailable)”
- **failureTag**: `keyword_zero_volume`
- **의미**:  
  - Naver SearchAd 등에서 가져온 키워드 검색량이 0이거나 미제공.  
  - 또는 `market_head`(예: “보험”)에 대한 검색량이 unavailable로 처리됨.

**로그 상 키워드**  
- 설계서 모드 displayKeywords: market_head(보험), product_core(미래에셋…), customer_concern(핵심 질환 보장이 약한 보험), persona_longtail(60대 여성 보험), intent_head(치매·장기요양).  
- 키워드 스코어링 상위는 “건강”, “의료보험”, “생명보험” 등이고, 상품·축과 직접 대응하는 키워드는 검색량이 없거나 적을 수 있음.

**원인 추정**  
- 설계서 모드에서 상품명/롱테일 위주 키워드는 검색량 데이터가 없거나 0으로 오는 경우가 많음.  
- 게이트는 “검색량이 있으면 건강, 없으면 경고”로 설계되어 있어, 이번처럼 데이터가 없으면 85점·keyword_zero_volume이 나옴.

**개선 제안**  
1. **설계서 모드 예외**: 설계서 전용 플로우에서는 keywordHealth를 “경고만 하고 감점은 완화” 또는 “미확인 시 스킵”하도록 옵션 추가.  
2. **데이터 보강**: Google/Naver 등에서 상품·축 관련 검색량을 더 보강하거나, unavailable일 때 대체 점수 로직 검토.
