# 정보성글 하루 1개 자동 생성 → 카페 업로드 구성안

## 하고 싶은 것

- **정보성 글**을 하루에 한 개씩 자동으로 만들고 **네이버 카페**에 자동 업로드
- **계정 구성 (본인 계정 2개, “각자 로그인” 방식 아님)**  
  - **아이디 1 — 회사용**: 정보성 글을 **카페에 자동 업로드**하는 용도. (스케줄러 + Playwright로 하루 1회 자동 실행.)  
  - **아이디 2 — 개인용**: **내 카페 키우기** + **개인 블로그 키우기** 용도. (Cursor + Browser MCP 등으로 필요할 때 직접 실행.)

---

## 1. 가능 여부

**가능합니다.** 회사용 1계정(자동) + 개인용 1계정(수동/반자동) 구성으로 나눠서 쓸 수 있습니다.

| 용도 | 계정 | 방식 |
|------|------|------|
| **정보성글 → 카페 자동 업로드** | 회사용 아이디 1개 | 스케줄러 + `POST /api/generate` + Playwright로 매일 1회 자동 실행. 해당 계정으로 지정 카페에만 올림. |
| **카페 키우기 + 개인 블로그 키우기** | 개인용 아이디 1개 | Cursor + Browser MCP 등으로 **필요할 때** 직접 실행. (자동 스케줄 아님.) |

---

## 2. 회사용(정보성글 카페 자동 업로드) — 필요한 것

**회사용 네이버 계정 1개**로, **매일 1회** 정보성 글을 생성해서 **지정한 카페**에만 자동으로 올리는 구성입니다.

### 2.1 필요한 요소

| 항목 | 내용 |
|------|------|
| **1) 글 생성** | 이미 있음. `POST /api/generate`로 주제·키워드 넣으면 정보성 블로그 HTML 생성. |
| **2) 스케줄러** | “하루에 한 번” 실행할 무언가. 예: **Vercel Cron**, **n8n**, **GitHub Actions**, 또는 소형 서버의 cron. |
| **3) 카페 업로드** | 네이버 카페는 공식 “글쓰기 API”가 없음. 그래서 **브라우저 자동화**가 필요함. |
| **4) 브라우저 자동화 (서버용)** | Cursor의 Browser MCP는 **사람이 Cursor 켜고 있을 때**만 동작함. 서버에서 “매일 정해진 시간에” 돌리려면 **Playwright** 또는 **Puppeteer** 같은 **헤드리스 브라우저 스크립트**를 서버/로컬에서 실행해야 함. |
| **5) 회사용 네이버 계정 1개** | 정보성글을 올릴 **회사용** 네이버 ID. 이 계정으로만 자동 업로드 스크립트가 동작함. 해당 카페 회원이어야 글쓰기 가능. |

### 2.2 회사용 자동 업로드 흐름 (예시)

```
[매일 09:00] 스케줄러 실행
    → (1) 오늘 쓸 주제/키워드 결정
    → (2) POST /api/generate 로 정보성 글 1개 생성
    → (3) Playwright: 회사용 계정 로그인 → 지정 카페·게시판 → 제목·본문 입력 → 발행
```

- **회사용 계정 1개**만 이 자동화에 사용. 개인용 계정(카페 키우기·개인 블로그)은 이 스크립트에 넣지 않음.

### 2.3 계정/보안

- **회사용** 네이버 ID·비밀번호(또는 로그인 세션)만 Playwright 스크립트에서 사용. 환경변수 또는 암호화 저장, 서버만 접근하도록.
- **개인용** 계정은 자동 스크립트에 넣지 않고, Cursor + Browser MCP로 필요할 때 본인 PC에서 직접 사용.

---

## 3. 개인용(카페 키우기 + 개인 블로그 키우기)

- **개인용 네이버 계정 1개**로 “내 카페 키우기” + “개인 블로그 키우기”를 할 때는 **자동 스케줄에 넣지 않음**.
- **방식**: Cursor + Browser MCP 사용. Chrome에 **개인용 네이버로 로그인**해 두고, Cursor 채팅에서  
  *“이 글을 ○○ 카페에 올려줘”*, *“내 블로그에 이 내용으로 글 써줘”* 처럼 요청.
- 회사용(정보성글 자동 업로드)과 **계정·용도를 분리**해서 쓰면 됨.

---

## 4. 정리

| 용도 | 계정 | 가능? | 필요한 것 |
|------|------|--------|------------|
| **정보성글 → 카페 자동 업로드** | 회사용 1개 | ✅ | 스케줄러 + `/api/generate` + Playwright + 회사용 네이버 계정 1개 |
| **카페 키우기 + 개인 블로그 키우기** | 개인용 1개 | ✅ | Cursor + Browser MCP, 개인용 네이버 로그인된 Chrome. (자동 스케줄 없음, 필요할 때 직접 실행) |

- **회사용**: 글 생성 API 이미 있음 → 스케줄러 + Playwright로 **회사용 계정만** 카페 업로드.
- **개인용**: Cursor에서 “이 글 내 카페/블로그에 올려줘” 요청 시 **개인용 Chrome(로그인된 계정)** 으로 올리면 됨. 각자 로그인·팀 단위 예약 발행은 사용하지 않음.

**다음 단계 (구현 시):**  
1) 스케줄러에서 매일 `POST /api/generate` 호출해 글 1개 생성.  
2) Playwright 스크립트: **회사용 계정 1개**만 설정 — 로그인 → 지정 카페·게시판 → 제목·본문 입력 → 발행.  
3) 설정: `{ id: '회사용ID', password: '...', cafe: '카페명', board: '게시판명' }` 형태로 환경변수 또는 암호화된 설정.

## 5. 정보성 글에 카카오페이 수익화(페이어텐션 등) 쓰기

**질문:** 정보성 글을 올리는 블로그/카페에 **카카오페이 ‘페이어텐션’**을 가져와서 쓸 수 있는지.

- **“페이어텐션”**이라는 이름의 카카오페이 공식 서비스는 검색·공개 자료에서 확인되지 않았습니다. 비슷한 이름(예: Pay Attention, 제휴/수익화 프로그램)일 수 있으니, **카카오페이 광고·제휴 안내**([kakaopay.com 광고안내](https://www.kakaopay.com/qna/advertising/onboarding)), **with 카카오 제휴**([with.kakao.com](https://with.kakao.com)) 또는 카카오페이 고객센터에서 정확한 프로그램명·가입 조건을 확인하는 것이 좋습니다.

- **일반적으로** 카카오/카카오페이 쪽 블로그·콘텐츠 연동은 다음과 같습니다.
  - **카카오 애드핏**: 블로그에 광고 배치 후 CPM 수익 (카카오 계정·사이트 등록 필요).
  - **with 카카오 제휴**: 인플루언서/콘텐츠 제휴(카카오페이 브랜드 활용 등).
  - **카카오페이 광고**: 기업용 광고 상품(전면 팝업, 송금완료 화면 등) — 블로그 직접 수익화보다는 광고주 측 서비스.

- **정보성 글에 “수익화 링크/배너”를 넣어 쓰는 것**은, 해당 프로그램의 **이용약관·가이드**를 만족하면 가능한 경우가 많습니다. 예: 글 본문이나 하단에 제휴 배너·링크를 넣고, 자동 생성 글의 HTML에 그 코드를 포함시키면 됩니다. 다만 **어떤 프로그램(페이어텐션 포함)을 쓰는지**에 따라 허용 플랫폼(네이버 블로그만 / 카페만 / 외부 블로그 등)이 다를 수 있으니, 반드시 해당 서비스 공식 안내를 확인하세요.

- **자동화와 연동:** “하루 1개 정보성 글 생성 → 카페 업로드”할 때, 생성되는 **HTML/본문에** 페이어텐션(또는 카카오페이 제휴) 배너/스크립트 코드를 미리 넣어 두면, 올라가는 글마다 그 수익화 요소가 포함되게 할 수 있습니다. (정책상 허용되는 경우에 한함.)

### 5.1 link.kakaopay.com(카카오페이 링크 페이지) 콘텐츠 가져오기

**질문:** [link.kakaopay.com](https://link.kakaopay.com) 주소에 있는 보험·생활 관련 글을 “가져와서” 쓸 수 있는지.

- **그곳이 어떤 곳인지**  
  예: `https://link.kakaopay.com/__/7umlbER` 같은 URL은 카카오페이가 운영하는 **콘텐츠 페이지**입니다. 뉴스 요약, 생활 정보, 하단에 굿딜/받아보기 등이 있는 형태로, 보험·생활 관련 기사도 비슷한 형식으로 올라올 수 있습니다.

- **기술적으로 “가져오기”**  
  - **읽기/수집**: URL을 열어서 HTML을 받고, 본문 텍스트만 추출하는 건 **가능**합니다. 이 프로젝트의 **fetch MCP**나 `mcp_web_fetch` 같은 도구로 `GET` 요청 후 HTML을 파싱해 텍스트를 뽑을 수 있습니다.  
  - 단, 페이지가 **JavaScript로 본문을 그리는 경우**에는 단순 HTTP GET만으로는 빈 화면이 올 수 있어, 그때는 **Playwright** 등 브라우저 자동화로 렌더링된 HTML을 가져오는 방식이 필요할 수 있습니다.  
  - **정리**: “그 주소의 보험/생활 내용을 우리 쪽에서 **읽어서 파싱**한다”는 건 기술적으로 구현 가능합니다.

- **이용 시 유의할 점 (저작권·이용약관)**  
  - 그 콘텐츠는 **카카오페이(또는 제휴 매체)**가 만든 **저작물**입니다.  
  - **그대로 복사해 내 블로그/카페에 올리면** 저작권·이용약관 위반 소지가 큽니다. “가져온다”고 하셔도 **원문 통째로 재게시**는 하지 않는 것이 안전합니다.  
  - **허용되는 활용 예**:  
    - **링크만 걸기**: “자세한 내용은 [여기(카카오페이 링크)](https://link.kakaopay.com/__/7umlbER)에서 보세요”처럼 **원문 링크**를 걸고, 우리 글은 요약·소개 수준으로만 작성.  
    - **참고만 하고 직접 작성**: 그 페이지를 **참고**해서, 보험/생활 주제를 **우리 말로 다시 쓰고** 원문 인용이 필요하면 짧게 인용+출처 링크.  
  - 제휴/수익화 프로그램(페이어텐션 등)에 가입해 있다면, **그 프로그램에서 허용하는 형태**(예: 공식 배너/링크 삽입, 문구 가이드 준수)로만 사용하는 것이 좋습니다.

- **정리**  
  - **가져올 수 있나?** → **읽어서 파싱하는 건 가능** (fetch/Playwright 등).  
  - **그 내용을 그대로 올려도 되나?** → **권장하지 않음.** 링크로 연결하거나, 참고해서 **우리 글로 다시 쓰고** 출처/링크만 넣는 방식이 안전합니다.
